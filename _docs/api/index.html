    @codewithrajat/universal-player - v0.0.1

    @codewithrajat/universal-player

    Framework-agnostic universal media player for video, audio, images and embeds.

    One headless TypeScript core, one <universal-player> web component, and thin adapters for React, Vue, Angular, Svelte 4 and Svelte 5. ESM-only, tree-shakeable, browser-first and dependency-free at the core.

    Status: experience release. Native playback, images, HLS, DASH, YouTube/Vimeo time sync, adaptive controls, chapters, playlists, thumbnails, caption menus, in-player surveys and a YouTube-style control surface are implemented. Cast, ads and VR remain contract-only. See docs/features.md.

    Why "universal"

    The player is not tied to <video>. It resolves a source into one of seven internal engines:

    Source Engine Runtime dependency
    .mp4, .webm, .mov, ... native none
    .mp3, .wav, .m4a, ... native none
    .jpg, .png, .avif, ... image none
    .m3u8 HLS optional hls.js
    .mpd DASH optional dashjs
    YouTube URLs iframe embed none
    Vimeo URLs iframe embed none
    Other iframe URLs generic embed none
    Chunked Blob/stream input chunked none
    data: URLs native/image none

    Engine selection is internal. The public API deliberately does not expose a plugin registry (see docs/decisions.md).

    Quick start

    1. Custom element (any framework, any page)

    <script type="module">
      import "@codewithrajat/universal-player";
      // Shadow DOM is the default and ships its own styles.
      // For light DOM, import the stylesheet and add shadow="light".
      import "@codewithrajat/universal-player/styles.css";
    </script>

    <universal-player
      src="/media/clip.mp4"
      poster="/media/poster.jpg"
      controls="custom"
      theme="dark"
      locale="en"
    ></universal-player>

    The element registers a UniversalPlayer instance and exposes it as element.player.

    2. Vanilla mount helper

    import { mountUniversalPlayer } from "@codewithrajat/universal-player/vanilla";
    import "@codewithrajat/universal-player/styles.css";

    const player = mountUniversalPlayer("#app", {
      source: "/media/clip.mp4",
      poster: "/media/poster.jpg",
      theme: "dark",
    });

    player.on("timeupdate", ({ currentTime, duration }) => {
      console.log(currentTime, duration);
    });

    3. Headless core

    import { createPlayer } from "@codewithrajat/universal-player/core";

    const player = createPlayer({
      container: document.querySelector("#app")!,
      source: "https://example.com/live.m3u8", // hls.js loaded lazily
      autoplay: false,
      muted: false,
    });

    await player.load("https://example.com/live.m3u8");
    await player.play();

    player.observe("statechange").subscribe((state) => {
      console.log(state.status, state.currentTime);
    });

    4. React

    import { UniversalPlayer } from "@codewithrajat/universal-player/react";
    import "@codewithrajat/universal-player/styles.css";

    export function Demo() {
      return (
        <UniversalPlayer
          src="/media/clip.mp4"
          poster="/media/poster.jpg"
          theme="dark"
          onEvent={(event) => console.log(event.type)}
        />
      );
    }

    A useUniversalPlayer() hook and an imperative UniversalPlayerHandle are also exported.

    5. Vue (2.7 and 3)

    <script setup lang="ts">
    import { UniversalPlayer } from "@codewithrajat/universal-player/vue";
    import "@codewithrajat/universal-player/styles.css";
    </script>

    <template>
      <UniversalPlayer src="/media/clip.mp4" theme="dark" />
    </template>

    6. Angular

    Angular libraries built by a generic bundler cannot safely ship a precompiled @Component, so this package ships a decorator-free controller. A standalone component you own forwards lifecycle calls to it:

    import { Component, ElementRef, ViewChild, type AfterViewInit } from "@angular/core";
    import { AngularUniversalPlayer } from "@codewithrajat/universal-player/angular";

    @Component({
      selector: "app-player",
      standalone: true,
      template: `<div #host></div>`,
    })
    export class PlayerComponent implements AfterViewInit {
      @ViewChild("host", { static: true }) host!: ElementRef<HTMLElement>;
      private controller!: AngularUniversalPlayer;

      ngAfterViewInit(): void {
        this.controller = new AngularUniversalPlayer({
          elementRef: this.host,
          inputs: { source: "/media/clip.mp4" },
        });
        this.controller.ngAfterViewInit();
      }
    }

    A complete standalone example lives in the Angular guide.

    Core API

    import { createPlayer, type PlayerState } from "@codewithrajat/universal-player/core";

    const player = createPlayer({
      container: element,
      source: "/media/clip.mp4",
      controls: "custom", // or "native"
      theme: "system", // "light" | "dark" | "system"
      locale: "en",
      resume: { enabled: true },
      analytics: { onEvent: (event) => console.log(event) },
    });

    await player.load("/media/clip.mp4");
    await player.play();
    player.pause();
    player.seek(30);
    player.setVolume(0.8);
    player.setMuted(true);
    player.setPlaybackRate(1.5);
    player.setQuality("720p"); // null = automatic
    player.setTextTrack("en"); // null = captions off
    player.setAudioTrack("commentary");
    player.seekToChapter("demo");
    await player.next();
    await player.openSurvey();
    await player.requestFullscreen();
    await player.requestPictureInPicture();
    player.destroy();

    State

    player.state is an immutable snapshot containing status, source, timing, volume, playback rate, quality, text/audio tracks, live/fullscreen/PiP flags and the last error.

    Three event styles

    // 1. Standard DOM events
    player.addEventListener("play", (event) => {
      console.log((event as CustomEvent).detail);
    });

    // 2. Typed subscriptions
    const unsubscribe = player.on("timeupdate", ({ currentTime }) => {
      console.log(currentTime);
    });
    unsubscribe();

    // 3. Observable streams (RxJS-compatible; no rxjs import required)
    player.observe("statechange").subscribe((state) => {
      console.log(state.status);
    });

    // Optional lazy RxJS bridge (only if rxjs is installed)
    import { toRxjsObservable } from "@codewithrajat/universal-player/core";
    const rx = await toRxjsObservable(player.observe("play"));

    Errors are plain Error objects with a stable code:

    import { isPlayerError } from "@codewithrajat/universal-player/core";

    try {
      await player.play();
    } catch (error) {
      if (isPlayerError(error)) {
        console.log(error.code); // "invalid-state", "media-error", ...
      }
    }

    Theming

    The built-in UI is neutral by default: progress fills, slider thumbs, selected menu items and focus rings use a white accent on dark themes (and dark ink on light themes). Set a brand colour per instance with the accent-color attribute:

    <universal-player src="/clip.mp4" accent-color="#22c55e"></universal-player>

    The same value is available through the JS/JSON API:

    createPlayer({
      container,
      source: "/clip.mp4",
      ui: { theme: { colors: { accent: "#22c55e" } } },
    });

    All visual tokens are CSS custom properties on .up-root/the host:

    universal-player {
      --up-color-accent: #22c55e;
      /* Text/icons drawn on top of the accent. Auto-derived by `accent-color`. */
      --up-color-accent-contrast: #06240f;
      --up-radius: 1rem;
      --up-font-family: "Inter", system-ui, sans-serif;

      /* Survey / feedback actions */
      --up-survey-button-radius: 999px;
      --up-survey-submit-bg: #22c55e;
      --up-survey-submit-color: #06240f;
      --up-survey-submit-hover-bg: #16a34a;
    }
    • theme="light" | "dark" | "system"
    • Shadow DOM by default (style isolation and built-in styles).
    • shadow="light" for light DOM; import styles.css or add inject-styles.
    • ::part(root|controls|play-button|...) is available for advanced styling.
    • Survey actions (Skip, Submit, Retake, Done) use a rounded text-button shape. Tune them with --up-survey-button-radius, --up-survey-submit-bg, --up-survey-submit-color, --up-survey-submit-hover-bg and --up-survey-submit-border.

    Internationalization

    Built-in strings are English. Register a locale or override per instance:

    import { registerLocale } from "@codewithrajat/universal-player/ui";

    registerLocale("hi", { play: "चलाएँ", pause: "रोकें" });

    const player = createPlayer({
      container,
      locale: "hi",
      strings: { play: "Start" },
    });

    The UI uses logical properties and works in RTL layouts.

    URL, stored and chunked media

    Every media type accepts the same source styles:

    // Remote URL
    await player.load("/media/clip.mp4");

    // Stored file / Blob / object URL / data URL
    await player.load(file);
    await player.load("data:image/png;base64,...");

    // A list becomes a playlist/gallery (images or clips)
    await player.load(["/photos/1.jpg", "/photos/2.jpg", "/photos/3.jpg"]);

    // Chunked upload or API response
    await player.load({
      kind: "video",
      type: "video/mp4",
      chunks: async function* () {
        const response = await fetch("/api/video");
        const reader = response.body!.getReader();

        while (true) {
          const { done, value } = await reader.read();
          if (done) return;
          yield value;
        }
      },
    });

    Chunked video/audio stream through MediaSource when the MIME type supports it and fall back to buffering into a Blob. Chunked images are assembled into a Blob. Pass a function that returns a fresh iterable/stream when the source must be replayable or reloadable.

    source: {
      kind: "video",
      type: "video/mp4",
      mode: "blob", // always buffer first
      chunks: () => fetchChunks(), // reusable
    }

    Playing a finished video automatically seeks back to 0 before replaying, so the same URL/source can be replayed without reloading it.

    For a photo slideshow, pass an array and set image.slideDuration:

    createPlayer({
      container,
      source: ["/photos/1.jpg", "/photos/2.jpg", "/photos/3.jpg"],
      image: { slideDuration: 5, zoom: true, rotate: true },
    });

    Captions and subtitles

    External WebVTT tracks can be supplied per source or per player. The CC button in the control bar toggles subtitles on/off immediately; open Settings → Subtitles/CC to choose a language, turn them off, or change the caption size. The same tracks are also available headlessly. Track choice and caption size are remembered per source.

    const player = createPlayer({
      container,
      source: {
        kind: "video",
        src: "/media/lecture.mp4",
        captions: [
          { src: "/media/en.vtt", label: "English", language: "en", default: true },
          { src: "/media/hi.vtt", label: "हिन्दी", language: "hi" },
        ],
      },
      captions: {
        enabled: true,
        defaultTrack: "en",
        style: { fontSize: "120%", color: "#fff", background: "rgba(0,0,0,.7)" },
      },
    });

    player.setTextTrack("hi");
    player.setTextTrack(null); // off
    player.toggleCaptions(); // keyboard: C
    player.setCaptionStyle({ fontSize: "140%" });

    Surveys, feedback and reviews

    Surveys are rendered inside the player, not on a separate page. Questions can come from the player config, from source metadata, or from an async provider (for example an API call when the video ends).

    const player = createPlayer({
      container,
      source: "/media/clip.mp4",
      survey: {
        id: "post-watch",
        kind: "feedback",
        title: "How was the video?",
        description: "This helps us improve the next one.",
        trigger: "ended", // or "manual" / seconds / { at: 120 }
        once: true,
        allowSkip: true,
        questions: [
          {
            id: "liked",
            type: "radio",
            label: "Did you like it?",
            required: true,
            options: [
              { id: "yes", label: "Yes" },
              { id: "no", label: "No" },
            ],
          },
          {
            id: "topics",
            type: "checkbox",
            label: "What should we cover next?",
            options: [
              { id: "api", label: "API design" },
              { id: "ui", label: "UI patterns" },
            ],
          },
          {
            id: "rating",
            type: "rating",
            label: "Rate this video",
            max: 5,
          },
          {
            id: "comment",
            type: "textarea",
            label: "Anything else?",
            maxLength: 500,
            allowOther: false,
          },
        ],
        onSubmit: async (result) => {
          await fetch("/api/feedback", {
            method: "POST",
            headers: { "content-type": "application/json" },
            body: JSON.stringify(result.answers),
          });
        },
      },
    });

    Supported question types: radio, checkbox, select, text, textarea, rating and scale. Choice questions support allowOther, minSelections, maxSelections; text questions support minLength/maxLength; numeric questions support min/max/step. Required validation is enforced by both the UI and the core.

    Submission is configurable:

    survey: {
      submitMode: "manual",       // "manual" | "on-select" | "on-complete"
      autoSubmit: true,           // shorthand for submitMode: "on-select"
      autoSubmitDelay: 0,         // ms before auto-submission
      required: true,             // cannot close/skip until submitted
      blocking: true,             // alias for required
      allowRetake: true,          // show a completion screen with Retake
      maxAttempts: 3,
      instantFeedback: true,      // quiz-style correct/incorrect feedback
      kind: "quiz",               // feedback/review never show correctness by default
      questions: [
        {
          id: "answer",
          type: "radio",
          label: "2 + 2?",
          required: true,
          correct: "4",
          explanation: "Four",
          options: [
            { id: "3", label: "3" },
            { id: "4", label: "4" },
          ],
        },
      ],
    }
    • on-select submits as soon as the required answers are selected.
    • on-complete submits when every required question is answered.
    • instantFeedback shows Correct/Incorrect and an explanation immediately for quiz questions.
    • feedback and review forms stay as a normal single form submission.
    • required/blocking hides skip/close and prevents the survey from being dismissed until it is submitted.
    • allowRetake (alias allowResubmit) keeps a thank-you screen open with Retake and Done actions. player.retakeSurvey() is also available headlessly, with maxAttempts controlling how many times.

    Dynamic or externally loaded questions:

    player.setSurvey(async () => {
      const response = await fetch("/api/survey");
      return response.json(); // SurveyConfig
    });

    await player.openSurvey(); // manual trigger

    Events and state:

    player.on("surveyopen", ({ survey }) => {});
    player.on("surveysubmit", ({ survey, answers, result }) => {});
    player.on("surveyskip", ({ survey }) => {});
    player.on("surveyclose", ({ survey, reason }) => {});
    console.log(player.state.survey, player.state.surveyOpen);

    Partial/required answers can be validated without opening the UI:

    import { validateSurveyAnswers } from "@codewithrajat/universal-player";

    Ready-made survey examples

    The package ships five copy-paste presets. Spread any preset and override only what you need:

    import {
      blockingReview,
      contentFeedback,
      endOfVideoFeedback,
      netPromoterScore,
      quizFeedback,
    } from "@codewithrajat/universal-player";

    const player = createPlayer({
      container,
      source: "/courses/lesson-1.mp4",
      survey: endOfVideoFeedback({
        title: "Was lesson one useful?",
        onSubmit: (result) => saveFeedback(result.answers),
      }),
    });
    Preset Use it for
    endOfVideoFeedback CSAT rating + topics + optional comment
    netPromoterScore NPS 0–10 + reason
    contentFeedback “Was this helpful?” with one-select auto-submit
    blockingReview Required review/notes before the viewer can continue
    quizFeedback Instant correct/incorrect quiz feedback

    The presets are plain SurveyConfig objects, so they also work from source metadata, player.setSurvey(), or the survey JSON attribute.

    Survey implementation checklist

    1. Pick a trigger: "ended", "manual", a number, or { at: 120 }.
    2. Decide whether the form is optional (allowSkip: true) or blocking (blocking: true, which also hides skip/close).
    3. Choose submission: manual, on-select, or on-complete.
    4. Persist once-per-source with once: true and a stable id.
    5. Submit to your API in onSubmit; listen to surveysubmit for analytics.
    6. Use maxAttempts + allowRetake for training/assessment flows.

    Adaptive controls

    The built-in UI reads state.kind and state.capabilities and only renders controls that make sense:

    Media Controls
    video Play, seek, time, volume, CC, settings, chapters, playlist, PiP, fullscreen
    audio Play, seek, time, volume, settings, playlist, loop, autoplay, fullscreen
    image Zoom in/out, rotate, download, share, fullscreen (no timeline or volume)
    embed Play, seek, time, volume, settings, fullscreen

    You can also drive the same surface headlessly; player.capabilities and player.state.capabilities are always in sync with the active engine.

    When the engine advertises more than one quality level (HLS/DASH, or an embed with configured qualities), Settings → Quality has −/+ steps plus Auto and every level. Single-file native media has one quality, so the option is not shown there. Stats for nerds also lives in Settings.

    Advanced control surface configuration

    Every control, menu section, gesture and colour can be configured. Use an allow-list when you want a minimal surface, or an object to hide individual controls. Every field is optional: omitted values keep the built-in defaults, and partial objects (for example settings: { stats: false }) only override the keys you provide.

    const player = createPlayer({
      container,
      source: "/media/clip.mp4",
      playlist: {
        items: [
          { source: "/media/lesson-1.mp4", title: "Lesson 1" },
          { source: "/media/lesson-2.mp4", title: "Lesson 2" },
        ],
        // The viewer must finish lesson 1 before Next becomes actionable.
        requireCompletion: true,
        // Or remove forward/backward navigation entirely:
        // allowNext: false,
        // allowPrevious: false,
      },
      ui: {
        // Allow-list: only these controls render.
        controls: ["play", "seek", "time", "volume", "captions", "settings", "fullscreen"],
        // Preferred order; omitted controls keep their default position.
        order: ["play", "volume", "time", "captions", "settings", "fullscreen"],
        settings: {
          speed: true,
          quality: true,
          captions: true,
          captionStyle: true,
          audio: true,
          loop: false,
          autoplay: true,
          autoplayNext: true,
          sleepTimer: true,
          stats: false,
          shortcuts: false,
        },
        speed: {
          enabled: true,
          rates: [0.5, 0.75, 1, 1.25, 1.5, 2],
          keyboard: false,
        },
        // Timestamp defaults to elapsed time; clicking it shows the remaining time.
        time: {
          mode: "elapsed",
          toggle: true,
          showTotal: true,
        },
        // Do not offer downloads at all.
        download: false,
        // Gestures are opt-in. Disable swipe-up, or disable all gestures.
        gestures: {
          enabled: true,
          swipeSeek: true,
          swipeFullscreen: true,
          swipeUp: false,
          swipeDown: true,
        },
        theme: {
          colors: { accent: "#ff0033" },
          radius: "0.9rem",
          menuBackground: "rgba(24, 24, 24, 0.82)",
          menuBlur: "16px",
          variables: { "--up-control-size": "2.75rem" },
        },
        showTitle: true,
        showChapterLabel: true,
        showTime: true,
        showBuffered: true,
        showPreview: true,
        showBigPlay: true,
        autoHideControls: true,
        idleDelay: 2500,
      },
    });

    Useful combinations:

    Goal Configuration
    Kiosk / no-forward course player playlist.requireCompletion: true, ui.controls allow-list
    No downloads ui.download: false
    No speed changes ui.speed: false
    No swipe-up fullscreen ui.gestures: { enabled: true, swipeUp: false }
    Disable all touch gestures ui.gestures: false
    Hide share/cast/PiP/previous/next ui.controls: { share: false, cast: false, ... }
    Brand colours without forking CSS ui.theme.colors + ui.theme.variables
    Start with remaining time ui.time.mode: "remaining"
    Keep the elapsed-only timestamp ui.time.toggle: false

    The timestamp is self-sizing: 1:02:03 for hour-long media, 2:03 for minute-long media, and 9s for clips shorter than a minute. Clicking it swaps the elapsed value for the remaining value (-7s / -1:51:03) while the tooltip keeps elapsed, remaining and total together. Open menus also close when the user clicks anywhere on the surrounding page, matching YouTube.

    The same options can be passed declaratively through a JSON ui attribute.

    Chapters, playlists and time sync

    const player = createPlayer({
      container,
      chapters: [
        { id: "intro", title: "Introduction", startTime: 0 },
        { id: "demo", title: "Demo", startTime: 90 },
      ],
      playlist: {
        items: [
          { source: "/media/one.mp4", title: "One" },
          { source: "/media/two.mp4", title: "Two" },
        ],
        autoAdvance: true,
        autoAdvanceDelay: 3,
      },

    await player.next();
    await player.previous();

    YouTube and Vimeo embeds mirror currentTime, duration, buffered progress and play/pause/ended state over postMessage. Call player.syncTime() for an immediate refresh.

    Keyboard shortcuts

    Space/K play-pause, M mute, F fullscreen, C subtitles on/off, S open Settings, Q open the quality sheet, [/] lower or raise quality, A open audio tracks, T open the sleep timer, R toggle loop, arrows seek and change volume, J/L seek 10s, 0–9 seek to a percentage, Home/End jump to start/end, </> change speed, N/P next/previous, I stats for nerds, ? shortcut help and Esc closes overlays. Shortcut hints are also shown beside the matching rows in the Settings sheet.

    Share and embed

    The share sheet includes native share, copy link, social targets and an Embed action that copies a ready-to-paste iframe snippet. The embed action is enabled by default and can be customised or disabled with ui.share:

    ui: {
      share: {
        url: "https://example.com/watch/clip", // optional share/embed URL
        title: "Lesson one",
        thumbnail: "/media/thumb.jpg",          // shown in the share sheet
        embed: {
          mode: "player",                       // "player" or "iframe"
          poster: "/media/thumb.jpg",
          width: 960,
          height: 540,
        },                                      // or embed: false
      },
    }

    Thumbnail images

    Thumbnails can be used in four places:

    • Poster before playback — set poster="/poster.jpg" (or the thumbnail alias) on <universal-player> / PlayerOptions.poster.
    • Seek-bar hover previews — pass thumbnails: { cues: [...] } or the thumbnails JSON attribute.
    • Share/embed preview — set ui.share.thumbnail and ui.share.embed.poster. When a poster is present the embed snippet uses the player mode automatically, or set mode: "iframe" to force an iframe.
    • Playlist/chapter thumbnails — set poster on playlist items or thumbnail on chapters; they render beside the item in the menu.

    Audio presentation

    Audio-only sources show an animated gradient and equalizer surface by default so the player still has a focused, eye-catching visual. If the audio source or playlist item supplies poster/thumbnail, that image is shown instead. Settings also exposes Autoplay and, for playlists, Autoplay next so the viewer can control automatic playback.

    Declarative configuration

    Complex options can be passed as JSON attributes:

    <universal-player
      src="/media/clip.mp4"
      chapters='[{"id":"a","title":"Intro","startTime":0}]'
      survey='{"title":"How was it?","questions":[{"id":"liked","type":"radio","label":"Liked?","options":[{"id":"yes","label":"Yes"},{"id":"no","label":"No"}]}]}'
      captions='{"tracks":[{"src":"/en.vtt","label":"English","language":"en"}]}'
      ui='{"speed":false,"download":false,"controls":{"share":false,"cast":false},"gestures":{"enabled":true,"swipeUp":false}}'
    ></universal-player>

    Accessibility

    Target: WCAG 2.2 AA.

    • Every control is a native <button>/<input>/<select>.
    • Visible focus rings and keyboard operation.
    • Shortcuts: Space/K play-pause, M mute, F fullscreen, C subtitles, S settings, [/] quality and arrows seek/change volume.
    • aria-label, aria-pressed, aria-valuetext, aria-busy and role="alert".
    • Reduced-motion and forced-colors media queries.

    A formal axe/Playwright audit is on the roadmap; see docs/features.md.

    Browser support

    Evergreen browsers, compiled to ES2023:

    • Chrome/Edge 125+
    • Firefox 128+
    • Safari 18+

    The package ships ESM only. CommonJS consumers must use dynamic import().
