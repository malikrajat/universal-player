## Quick Start


`@codewithrajat/universal-player` is a framework-agnostic media player for JavaScript and TypeScript that plays **video, audio, still images and third-party embeds** through one API. It ships a headless TypeScript core, one `<universal-player>` custom element with the full built-in UI, and adapters for React, Vue, Angular, Svelte 4 and Svelte 5. A source is resolved into one of eight internal engines — native, image, chunked, HLS, DASH, YouTube, Vimeo and generic embed — with optional `hls.js`/`dashjs` peers loaded only when needed.

The package is ESM-only, browser-first, dependency-free at the core and validated with strict TypeScript, publint, attw, a tarball allowlist and a browser-import scan.

> **Publication status:** `@codewithrajat/universal-player@0.0.1` is **not published on the public npm registry**. Registry commands below are intended-only. Build the repository and install it from the folder (`pnpm add file:/absolute/path/to/universal-player`) or a packed tarball until a release exists.

> **Status: experience release.** Native playback, images, HLS, DASH, YouTube/Vimeo time sync, adaptive controls, chapters, playlists, thumbnails, caption menus, in-player surveys and a YouTube-style control surface are implemented. Ads, Chromecast SDK and 360/VR remain contract-only. See [docs/features.md](./docs/features.md).

### Installation

```bash
# Intended command after a public release
npm install @codewithrajat/universal-player

# Today: install from the repository folder
pnpm install
pnpm build
pnpm add file:/absolute/path/to/universal-player
```

### Basic Usage

```html
<script type="module">
  import "@codewithrajat/universal-player";
</script>

<universal-player
  src="/media/clip.mp4"
  poster="/media/poster.jpg"
  controls="custom"
  theme="dark"
  locale="en"
></universal-player>
```

The element registers the built-in UI and exposes the live core instance as `element.player`. Because Shadow DOM is the default, the component ships its own styles — `styles.css` is only required when you opt into `shadow="light"`.

## Features

- **Universal source resolution**: One source pipeline resolves URLs, `Blob`/`File`, `MediaStream`, `data:` URLs, arrays and chunk streams into eight internal engine providers — no plugin registry, no engine guessing in application code
- **Native video and audio**: MP4, WebM, MOV, MP3, M4A, WAV, FLAC, Ogg and raw AAC through the browser's own media stack, with per-kind capability detection
- **Image engine**: JPEG, PNG, WebP, AVIF, GIF and SVG with zoom, rotate, download, gallery slideshow and poster support
- **HLS and DASH**: `.m3u8` through lazy `hls.js` (or native HLS in Safari) and `.mpd` through lazy `dashjs`, with quality levels exposed to the settings menu
- **YouTube and Vimeo time sync**: Commands plus `currentTime`, `duration`, buffered progress and play/pause/ended state mirrored over `postMessage`
- **Generic iframe embeds**: Render any embed URL without pretending a command bridge exists
- **Stored and chunked media**: Object URLs are owned and revoked; chunked video/audio streams through `MediaSource` when supported and falls back to Blob buffering
- **One headless core, three event styles**: DOM `addEventListener`, typed `on`/`once` subscriptions and RxJS-compatible observables from one event bus
- **Immutable state**: `player.state` is a frozen snapshot covering status, source, timing, volume, rate, quality, tracks, chapters, playlist, survey, live, fullscreen, PiP and the last error
- **Full UI in one custom element**: `<universal-player>` renders the control bar, settings sheet, chapter menu, playlist menu, share sheet, survey overlay, error overlay and stats panel
- **Adaptive controls**: The UI reads `state.kind` and `state.capabilities` and only renders controls that make sense for video, audio, images or embeds
- **Configurable control surface**: Allow-list, hide or reorder controls; configure settings sections, speed rates, timestamp behaviour, downloads, share/embed, gestures and layout flags
- **Quality and speed**: HLS/DASH level lists, `−`/`+` quality steps, Auto, and playback rates from `0.25×` to `4×`
- **Captions**: External WebVTT tracks, CC quick toggle, language menu, caption sizing, persistence per source and headless track APIs
- **Chapters and thumbnails**: Timeline markers, chapter list, active chapter label, next/previous chapter seek, seek-bar hover previews, poster and playlist/chapter artwork
- **Playlists**: Auto-advance, auto-advance delay, loop, next/previous, completion gating and image galleries
- **In-player surveys**: Feedback, review, NPS and quiz forms with radio, checkbox, select, text, textarea, rating and scale questions, validation, auto-submit, instant feedback, retakes and five copy-paste presets
- **Resume, live and stats**: Storage-backed resume, live state and seekable helpers, live label, and a Stats for Nerds panel for resolution, frames, buffer, quality, tracks and network
- **Theming and i18n**: CSS custom properties, `::part()` styling, light/dark/system themes, `accent-color`, locale registration, per-instance string overrides and RTL layout
- **Keyboard and accessibility**: Full YouTube-style shortcut set with a help overlay, native controls, visible focus, ARIA state, reduced-motion and forced-colors support — WCAG 2.2 AA-oriented markup
- **Share and embed**: Native share, copy link, social targets and a ready-to-paste iframe or player snippet with poster preview
- **Analytics hooks**: Six vendor-neutral event types (`loadedmetadata`, `play`, `pause`, `seeked`, `ended`, `error`) through a single safe sink
- **Framework adapters**: React hook and component, Vue 2.7/3 component and composable, Angular decorator-free controller, Svelte 4 and Svelte 5 components, plus `mountUniversalPlayer()` for vanilla apps
- **Zero runtime dependencies**: `dependencies` is empty; `hls.js`, `dashjs`, `rxjs` and framework packages are optional peers
- **Tiny and tree-shakable**: Unbundled ESM, static entry points and a `sideEffects` allowlist limited to CSS and the two registering entries
- **Strict TypeScript**: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `verbatimModuleSyntax`, with bundled `.d.ts` per entry and nine stable error codes
- **Validated packaging**: publint, attw with the ESM-only profile, tarball allowlist, Node-builtin import scan, CycloneDX SBOM and Changesets-based releases
- **Deterministic tests**: Vitest with jsdom for unit behaviour, Vitest browser mode with Playwright for APIs jsdom cannot model, and coverage gates on the core and key features

### 2. Basic Integration

#### Option A: Full UI custom element (Recommended)

```html
<script type="module">
  import "@codewithrajat/universal-player";
</script>

<universal-player
  src="/media/clip.mp4"
  poster="/media/poster.jpg"
  controls="custom"
  theme="dark"
  locale="en"
  label="Product tour"
></universal-player>
```

The element registers the built-in UI immediately. Read or drive playback through the live instance:

```ts
const element = document.querySelector("universal-player");
const player = element.player;

player.on("timeupdate", ({ currentTime, duration }) => {
  console.log(currentTime, duration);
});
```

#### Option B: Headless core (your own controls)

`createPlayer()` mounts the media surface and exposes state, methods and events. It never renders the built-in control bar.

```ts
import { createPlayer } from "@codewithrajat/universal-player/core";

const player = createPlayer({
  container: document.querySelector("#app")!,
  source: "/media/clip.mp4",
  controls: "native", // or "custom" when you render your own chrome
  poster: "/media/poster.jpg"
});

player.on("statechange", (state) => {
  console.log(state.status, state.currentTime);
});

await player.play();
```

| Entry point          | Use it for                                             | Renders built-in chrome? |
| -------------------- | ------------------------------------------------------ | ------------------------ |
| `<universal-player>` | Complete UI on any page or inside any framework        | Yes                      |
| `createPlayer()`     | Headless playback with your own controls               | No                       |
| Framework adapters   | Headless playback inside React, Vue, Angular or Svelte | No                       |

**Only `<universal-player>` renders the built-in UI.** The framework adapters and `mountUniversalPlayer()` mount the core, not the element. Use `controls: "native"` for browser controls, mount the custom element for the full UI, or build your own chrome from `player.state` and methods.

### 3. Common Use Cases

#### Building a Course Player with a Gated Playlist

```ts
import { createPlayer } from "@codewithrajat/universal-player/core";

const player = createPlayer({
  container: document.querySelector("#course")!,
  source: lessons[0].source,
  playlist: {
    items: lessons,
    requireCompletion: true,
    allowPrevious: false,
    autoAdvance: true,
    autoAdvanceDelay: 3
  }
});

await player.play();
```

Gating is enforced in the core, not only in the UI. `next()` throws `invalid-state` before the current item ends, and the same rule applies to keyboard and programmatic calls.

#### Using the React Adapter

```tsx
import { UniversalPlayer } from "@codewithrajat/universal-player/react";

export function Lesson() {
  return (
    <UniversalPlayer
      source="/media/lesson.mp4"
      poster="/media/poster.jpg"
      controls="native"
      onEvent={(event) => console.log(event.type)}
    />
  );
}
```

The [`/react`](./examples/react/README.md), [`/vue`](./examples/vue/README.md), [`/angular`](./examples/angular/README.md), [`/svelte4`](./examples/svelte/README.md) and [`/svelte5`](./examples/svelte/README.md) entries are headless. Use the custom element when you want the built-in UI inside a framework, or use the adapter and render your own controls.

#### Playing a User-Selected File or an API Stream

```ts
// A user-selected File or Blob — the player owns and revokes the object URL.
await player.load(file);

// A chunked API response — MediaSource when supported, Blob fallback.
await player.load({
  kind: "video",
  type: "video/mp4",
  chunks: async function* () {
    const response = await fetch("/api/video");
    const reader = response.body!.getReader();

    while (true) {
      const { done, value } = await reader.read();
      if (done) return;
      yield value;
    }
  }
});
```

### 5. Programmatic Control

```ts
import { createPlayer } from "@codewithrajat/universal-player/core";

const player = createPlayer({
  container: document.querySelector("#app")!,
  source: "/media/clip.mp4"
});

await player.load("/media/clip.mp4");
await player.play();
player.pause();
player.seek(30);
player.setVolume(0.8);
player.setMuted(true);
player.setPlaybackRate(1.5);
player.setQuality("720p"); // null = automatic
player.setTextTrack("en"); // null = captions off
player.setAudioTrack("commentary");
player.seekToChapter("demo");
await player.next();
await player.openSurvey();
await player.requestFullscreen();
await player.requestPictureInPicture();

player.destroy(); // terminal: releases the engine, timers and object URLs
```

Every failure is a plain `Error` with a stable `code`. Branch on the code, never on the message:

```ts
import { isPlayerError } from "@codewithrajat/universal-player/core";

try {
  await player.play();
} catch (error) {
  if (isPlayerError(error)) {
    console.log(error.code); // "invalid-state", "media-error", ...
  }
}
```

The built-in UI is a full control surface, not a thin wrapper around native controls. It includes a YouTube-style bar, translucent settings submenus, chapter markers, buffered rail, hover previews, playlist menu, share/embed sheet, sleep timer, stats for nerds, shortcut help, error overlay with retry and an in-player survey dialog.

```ts
  },
  captions: {
    enabled: true,

  survey: {
    id: "post-watch",
    kind: "feedback",
    title: "How was the video?",
    trigger: "ended",
    once: true,
    allowSkip: true,
    questions: [
      {
        id: "rating",
        type: "rating",
        label: "Rate this video",
        max: 5
      },
      {
        id: "comment",
        type: "textarea",
        label: "Anything else?",
        maxLength: 500
      }
    ],
    onSubmit: async (result) => {
      await fetch("/api/feedback", {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify(result.answers)
      });
    }
  }
});

player.toggleCaptions();
player.setTextTrack("hi");
player.setCaptionStyle({ fontSize: "140%" });
```

Survey state and events are available headlessly:

```ts
player.on("surveyopen", ({ survey }) => {});
player.on("surveysubmit", ({ survey, answers, result }) => {});
player.on("surveyskip", ({ survey }) => {});
player.on("surveyclose", ({ survey, reason }) => {});

console.log(player.state.survey, player.state.surveyOpen);
```

The package ships five copy-paste presets: `endOfVideoFeedback`, `netPromoterScore`, `contentFeedback`, `blockingReview` and `quizFeedback`. The presets are plain `SurveyConfig` objects, so they also work from source metadata, `player.setSurvey()` or the `survey` JSON attribute.

## Installation & Setup

For detailed installation instructions, see the
[Getting Started guide](./docs/getting-started/installation.md).

The package has no runtime dependencies and ships ESM only. It does not require a
bundler, but the browser must be able to resolve the package export map:

```html
<script type="module">
  import "@codewithrajat/universal-player";
</script>

<universal-player
  src="/media/clip.mp4"
  poster="/media/poster.jpg"
  controls="custom"
  theme="dark"
></universal-player>
```

Without a bundler, point the bare specifier at the built ESM files with an import
map or a CDN that serves the package. Shadow DOM is the default and ships its own
styles; add `shadow="light"` and import `@codewithrajat/universal-player/styles.css`
only when you need light-DOM integration.

## FAQ

<details>
<summary><strong>What exactly does Universal Player play?</strong></summary>

**Video, audio, still images and third-party embeds** through one API. A source is
normalised into one of eight internal engines: native, image, chunked, HLS, DASH,
YouTube, Vimeo and generic embed. The player does not transcode and does not parse
media containers itself; codec and container support remain the browser's
responsibility.

</details>

<details>
<summary><strong>Is it a wrapper around Video.js, Plyr or Shaka Player?</strong></summary>

**No.** It has its own core, adapters and UI. It optionally uses `hls.js` and
`dashjs` for streaming, but neither is required for native media, images or embeds.

</details>

<details>
<summary><strong>Does it send data anywhere or need a backend?</strong></summary>

**No.** The package contains no endpoints, no analytics account and no upload path.
`analytics.onEvent` is a local callback you provide; it does nothing unless you wire
it. Resume and caption persistence use `localStorage` and can be disabled.

</details>

<details>
<summary><strong>Which frameworks and browsers are supported?</strong></summary>

React 18/19, Vue 2.7 and Vue 3, Angular 17+, Svelte 4 and Svelte 5, plus vanilla
ESM. The core is framework-agnostic. Declared browser minimums are Chrome/Edge
125+, Firefox 128+ and Safari 18+, compiled to ES2023. These are declared minimums,
not an automated cross-browser matrix; the executed browser test is Chromium.

</details>

<details>
<summary><strong>Is it safe to import during server-side rendering?</strong></summary>

**Importing `/core` is safe**, but constructing a player requires a DOM container,
and the package does **not** support SSR rendering of the element or framework
wrappers. Use a client-only boundary: `dynamic(..., { ssr: false })` in Next.js,
`<ClientOnly>` in Nuxt, `onMount` in SvelteKit or `isPlatformBrowser` in Angular
Universal.

</details>

<details>
<summary><strong>Do I need to install hls.js or dashjs?</strong></summary>

Only if you load HLS or DASH sources. Both are optional peers and are lazily
imported by the matching engine. Safari can play HLS natively; DASH generally
requires `dashjs`.

</details>

<details>
<summary><strong>Why is the package ESM-only?</strong></summary>

It targets modern browsers and bundlers, avoids the dual-package hazard and keeps
the export map small. There is no `require()` entry; CommonJS consumers can use
dynamic `import()`.

</details>

<details>
<summary><strong>Why does the React/Vue/Angular/Svelte adapter show no controls?</strong></summary>

Because the adapters are **headless**. They mount a media surface and expose state,
methods and events; they do not render the built-in control bar. Use
`controls: "native"` for browser controls, mount `<universal-player>` for the full
UI, or build your own chrome from `player.state`.

</details>

<details>
<summary><strong>How do I prevent viewers from skipping ahead in a course?</strong></summary>

Use a playlist with completion gating:

```ts
playlist: {
  items: lessons,
  requireCompletion: true,
  allowPrevious: false
}
```

The rule is enforced in the core, including keyboard shortcuts and programmatic
`next()` calls — not just hidden in the UI.

</details>

<details>
<summary><strong>How do I load a user-selected file or an API stream?</strong></summary>

Pass a `File`/`Blob` directly, or a chunked source for an API response:

```ts
await player.load(file);

await player.load({
  kind: "video",
  type: "video/mp4",
  chunks: fetchChunks
});
```

The player owns and revokes object URLs. Chunked video/audio uses `MediaSource`
when supported and falls back to Blob buffering.

</details>

<details>
<summary><strong>Can I play YouTube or Vimeo?</strong></summary>

**Yes**, by URL or structured embed source. Time, duration, buffered progress and
play/pause/ended state are mirrored over `postMessage`. Provider restrictions still
apply; some videos disallow embedding. Generic iframes render without a command
bridge.

</details>

<details>
<summary><strong>Can I customise the controls without forking the UI?</strong></summary>

**Yes.** Use an allow-list, hide individual controls or define an order:

```ts
ui: {
  controls: ["play", "seek", "time", "volume", "captions", "settings", "fullscreen"],
  order: ["play", "volume", "time", "captions", "settings", "fullscreen"],
  settings: { stats: false, shortcuts: false },
  download: false,
  gestures: { enabled: true, swipeUp: false }
}
```

Every section is optional; omitted values keep the built-in defaults.

</details>

<details>
<summary><strong>How do I theme the player?</strong></summary>

Set a brand colour with `accent-color` or override tokens:

```html
<universal-player src="/clip.mp4" accent-color="#22c55e"></universal-player>
```

```css
universal-player {
  --up-color-accent: #22c55e;
  --up-radius: 1rem;
  --up-font-family: "Inter", system-ui, sans-serif;
}
```

Shadow DOM is the default. Use `::part(root|controls|play-button|...)` for advanced
styling, or switch to `shadow="light"` and load `styles.css`.

</details>

<details>
<summary><strong>Why did <code>play()</code> throw <code>invalid-state</code>?</strong></summary>

No source is loaded, the operation does not fit the current lifecycle, or the player
has been destroyed. Check `player.state.status` and `player.state.error`; load a
source first with `load()`, and create a new player after `destroy()`.

</details>

<details>
<summary><strong>Why does <code>statechange</code> not fire on every <code>timeupdate</code>?</strong></summary>

High-frequency `timeupdate` and `progress` patches update state without emitting a
second `statechange`. Subscribe to `timeupdate` for progress and use `statechange`
for meaningful transitions such as play, pause, seek completion or track changes.

</details>

<details>
<summary><strong>Does it support DRM?</strong></summary>

**No.** DRM (Widevine/FairPlay/PlayReady) is explicitly out of scope for `0.0.1`.
The player does not include EME or license-server integration.

</details>

<details>
<summary><strong>How large is the package, and will it bloat my bundle?</strong></summary>

The core has zero runtime dependencies, the output is unbundled ESM and `sideEffects`
is limited to CSS and the two registering entries, so unused adapters and features are
tree-shaken. Streaming SDKs and frameworks are optional peers. A bundle budget is not
enforced yet; inspect `dist/entries/core.js` and its imports after `pnpm run build`.

</details>

<details>
<summary><strong>Is it production-ready?</strong></summary>

`0.0.1` is an **experience release**. Implemented: native playback, images, HLS,
DASH, embeds, chunked sources, adaptive controls, captions, chapters, playlist,
surveys, resume, analytics, theming, i18n, shortcuts and six adapter surfaces. Partial:
live/DVR UI. Scaffolded: ads, Chromecast SDK, 360/VR and a formal axe audit. Out of
scope: DRM, SSR and a public plugin registry. Read [docs/features.md](./docs/features.md)
before committing to a scaffolded area.

</details>

<details>
<summary><strong>How do I report a bug or a security issue?</strong></summary>

Bugs: open a GitHub issue with the bug report template and include the package
version, browser/OS, entry point, media source type and a minimal reproduction.
Security: follow [SECURITY.md](./SECURITY.md) and do **not** open a public issue with
exploit details.

</details>

<details>
<summary><strong>Is this library free for commercial use?</strong></summary>

**Yes.** Licensed under **MIT** — use it in commercial products, SaaS applications and
enterprise projects. You only need to retain the copyright notice. See the
[License](#license) section.

</details>

## Performance Optimization

### Optimization Tips

#### 1. Keep the Import Surface Small

```ts
// Headless core only
import { createPlayer } from "@codewithrajat/universal-player/core";

// UI only when you need the built-in element
import "@codewithrajat/universal-player/ui";
```

Avoid importing the root when you only need playback; the root also pulls in the
custom element, i18n and feature helpers. Framework adapters import only the
framework you use.

#### 2. Do Not Recreate Players

```ts
// Good: one player for the lifetime of the surface
const player = useMemo(
  () => createPlayer({ container, source }),
  [container, source]
);

useEffect(() => () => player.destroy(), [player]);

// Bad: a new player on every render
const player = createPlayer({ container, source });
```

Framework adapters already own creation and teardown. Recreating on every render is
expensive and loses playback position.

#### 3. Throttle High-Frequency Work

```ts
import { throttle } from "lodash-es";

player.on(
  "timeupdate",
  throttle(({ currentTime }) => updateProgress(currentTime), 250)
);
```

`timeupdate` typically fires 4–10 times per second. Do not call framework state
setters on every tick if the UI does not need it. Use `statechange` for full
re-renders.

#### 4. Preload Deliberately

```ts
createPlayer({ container, source, preload: "metadata" });
```

`metadata` loads dimensions and duration without the full file; `none` avoids
network until play; `auto` may download aggressively. On pages with many players,
prefer `none` or `metadata`, and keep one player per surface.

#### 5. Keep Streaming SDKs on the Routes That Need Them

```ts
// Only the live route imports hls.js at runtime.
const player = createPlayer({ container, source: "/live/index.m3u8" });
```

HLS and DASH peers are dynamically imported by the matching engine. Do not import
`hls.js` yourself just to pass it in, and do not preload every caption language if
bandwidth matters. Use a sprite sheet for dense thumbnail previews.

### Unit Testing with Vitest

```ts
import { describe, expect, it } from "vitest";
import { createPlayer } from "../src/entries/core.js";

describe("player", () => {
  it("starts idle", () => {
    const container = document.createElement("div");
    const player = createPlayer({ container });

    expect(player.state.status).toBe("idle");
    expect(player.state.volume).toBe(1);

    player.destroy();
  });

  it("rejects play without media", async () => {
    const container = document.createElement("div");
    const player = createPlayer({ container });

    await expect(player.play()).rejects.toMatchObject({ code: "invalid-state" });

    player.destroy();
  });
});
```

For playlist gating, survey validation and resume, use a fake `Storage` and assert
the public behaviour — not private fields:

```ts
import { validateSurveyAnswers } from "@codewithrajat/universal-player";

const issues = validateSurveyAnswers(survey, answers);
expect(issues).toEqual([]);
```

```ts
import { test, expect } from "@playwright/test";

test("renders the custom element and starts playback", async ({ page }) => {
```

## Troubleshooting

### Common Issues

#### Issue: nothing renders

```ts
// Check the chain in order:
customElements.get("universal-player"); // undefined => not registered
document.querySelector("universal-player")?.player; // null => not connected
```

Import the root or `/ui`, ensure the element is connected to the DOM, give the host a
size and check the console for a `PlayerError`.

#### Issue: player has zero height

```css
universal-player,
.player-host {
  display: block;
  inline-size: 100%;
  aspect-ratio: 16 / 9;
}
```

Percentage-height children need a sized parent. Use `aspect-ratio` for video, a fixed
height for audio and `min-height` for images.

#### Issue: HLS or DASH fails

```bash
pnpm add hls.js
pnpm add dashjs
```

Add CORS to the **manifest and every segment**, use the correct MIME type
(`application/vnd.apple.mpegurl` or `application/dash+xml`) and verify that manifest
URLs resolve. A manifest that loads while segments fail is the most common cause.

#### Issue: controls look unstyled

Import the stylesheet when using light DOM:

```html
<script type="module">
  import "@codewithrajat/universal-player";
  import "@codewithrajat/universal-player/styles.css";
</script>

<universal-player shadow="light" ...></universal-player>
```

Or add the `inject-styles` attribute. Shadow DOM should not need the stylesheet.

#### Issue: `document is not defined` during SSR

`core` imports safely, but constructing a player needs a DOM. Use a client-only
boundary (`dynamic(..., { ssr: false })`, `<ClientOnly>`, `onMount`,
`isPlatformBrowser`). See [SSR guidance](./docs/browser-support.md#8-ssr-frameworks).

#### Issue: next is blocked

```ts
console.log(player.playlistStatus);
```

`requireCompletion` blocks advancing before the item ends; `allowNext: false` blocks
it entirely; `loop: false` returns `null` at the end. Change the playlist options or
wait for `ended`.

#### Issue: a method throws a `PlayerError`

| Code                      | Likely fix                                          |
| ------------------------- | --------------------------------------------------- |
| `invalid-state`           | Load a source first; check playlist gating.         |
| `invalid-argument`        | Bad container, empty source list or survey answers. |
| `unsupported-source`      | PiP on non-video, unsupported provider.             |
| `unsupported-environment` | Fullscreen/PiP/object URLs unavailable.             |
| `network-error`           | CORS, 404, offline.                                 |
| `media-error`             | Codec, decoder or lazy SDK failure.                 |
| `aborted`                 | A newer load superseded the old one.                |
| `destroyed`               | You called a method after `destroy()`.              |
| `not-implemented`         | Ad stub used without an SDK adapter.                |

## Best Practices

### 1. Choose the Lowest API Level That Fits

| Need                                        | Use                              |
| ------------------------------------------- | -------------------------------- |
| Complete UI, any page                       | `<universal-player>`             |
| Complete UI inside React/Vue/Angular/Svelte | `<universal-player>` after `/ui` |
| Headless playback in a framework            | Framework adapter                |
| Your own buttons                            | `/core` or the framework hook    |
| No UI at all                                | `/core`                          |

Do not re-implement the built-in surface unless you need a fundamentally different
interaction model. It already handles adaptive controls, captions menus, gestures,
surveys, sleep timer and ARIA. Framework adapters do not include it.

### 2. Give the Host a Size

```css
.player {
  inline-size: 100%;
  aspect-ratio: 16 / 9;
  background: #000;
}
```

The player fills its container. A percentage-height child inside an auto-height parent
collapses to zero. Use a fixed height for audio and `min-height` for images.

### 3. Always Destroy

```ts
useEffect(() => {
  const player = createPlayer({ container, source });
  return () => player.destroy();
}, []);
```

`destroy()` releases the engine, timers, document listeners and object URLs. Skipping
it leaks memory on route changes and in tests. Framework adapters already do this; if
you use the vanilla mount or core directly, you own it.

### 4. Theme with Tokens, Not Overrides

```css
/* Good: token */
universal-player {
  --up-color-accent: #22c55e;
}

/* Fragile: reaching into shadow internals */
```

Use `::part()` for structure and tokens for colour/shape. Avoid `!important` rules
against internal classes. Keep visible focus and check contrast after changing the
accent.

### 5. Gate Navigation in the Core, Not Just in CSS

```ts
playlist: { requireCompletion: true, allowPrevious: false }
```

Hiding buttons is not enforcement. The core checks the same rules for keyboard
shortcuts and programmatic `next()` calls. Validate survey answers on the client for
UX and on the server for trust.
